Synthetic Data

Synthetic data means examples — like coding problems, solutions, explanations — made by a computer program instead of collected from humans. In the reasoning-model arc, after the model learns to predict text, it needs thousands or millions of new examples to learn how to think and explain answers step-by-step. Creating these examples by hand would take forever, so a strong model generates them automatically.

First Principles

Real human examples are expensive and slow to gather. A model or simulator can make new training examples in three ways: (1) generate a question or task, (2) solve it, and (3) write reasoning steps along the way. For example, a program can ask 'write a Python function that sorts a list,' then run the solution to confirm it works, then keep only correct answers. The real work is checking that these made-up examples are actually useful for teaching — that the generated reasoning teaches real problem-solving, not just fluent-sounding nonsense.

Concrete Example

Take a strong coding model. Feed it a prompt: 'Generate 100 unique coding problems with solutions and test cases.' It produces 100 tasks, writes Python code for each, and runs the tests. Some solutions fail their tests — those get thrown out. The 80 passing solutions become training data. Later, a smaller model trains on those 80 examples, learning both how to code and how to explain its reasoning by showing the steps it took.

Why It Matters

Synthetic data is how modern reasoning models scale up their training. A model like GPT or Qwen starts by reading mountains of text and learning to predict the next word — that is pretraining, the first learning phase. Then it needs to learn reasoning and problem-solving through thousands of step-by-step examples. Without synthetic data, you would need to hire thousands of people to write those examples. Synthetic data lets you generate them in minutes. But the catch is real: if the synthetic data is sloppy or full of mistakes, the model learns those mistakes. If it copies patterns without understanding, the model copies, not thinks. So you have to be very careful to verify that what you generate is actually correct and teaches thinking, not imitation.

Common Misunderstanding

Many people think synthetic data is a shortcut and produces weak results. The truth is more precise: unverified synthetic data often is weak or harmful — it teaches wrong answers and bad reasoning. But synthetic data that is carefully checked (answers tested, reasoning traced, mistakes rejected) can be better than real human examples. The difference is verification. A model generating 1 million coding problems sounds great; 1 million problems with every solution tested against a suite of unit tests is powerful; 1 million problems where someone just eyeballed 50 of them is dangerous.

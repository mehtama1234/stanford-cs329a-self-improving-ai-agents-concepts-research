Test-Time Compute

Test-time compute means spending more computation when answering a question, without changing the model weights.

First Principles

If a model has a distribution containing both weak and strong paths, extra runtime computation can search that distribution, generate multiple candidates, revise intermediate work, or verify outputs. The model stays fixed, but the inference procedure becomes stronger.

Concrete Example

Instead of asking for one answer to a coding problem, generate 50 programs, run unit tests, and keep the one that passes.

Why It Matters

This is central to reasoning models and agents because many hard tasks are not solved by one forward pass. They require search, checking, retries, and budget allocation.

Common Misunderstanding

Test-time compute is not free intelligence. It only helps when there is a way to select better outputs or use feedback.

Deep Research Agents

Deep research agents search across sources, decide what is relevant, synthesize evidence, and produce a structured answer or report.

Ordinary Problem

Research work is not one lookup. It requires source discovery, relevance filtering, synthesis, citation, and uncertainty handling.

Naive Picture

Deep research is just summarizing more documents after collecting a larger pile of sources.

Why It Fails

The hard part is deciding what to search, what to trust, how to combine sources, and when enough evidence has been gathered.

First-Principles Move

Research is an agent loop over information: ask, search, read, update beliefs, search again, synthesize, and cite.

What Breaks Without It

The report becomes a fluent collage with weak source control.

Course Role

Parts 1, 7, and 9 repeatedly use deep research as a central agent workflow.

Worked Example

A research agent is given the query: 'Calculate the carbon atom count in Product 3 of this multi-step chemical reaction.' Vanilla reasoning fails because the model encounters an unfamiliar chemical term and guesses, leading to an incorrect final answer of 10 carbon atoms. Simple RAG retrieves 10 Wikipedia documents on the chemistry, but the model drowns in irrelevant text and still answers incorrectly (14 atoms).

Search-o1 operates iteratively: when the model generates the word 'perhaps' (uncertainty marker), it triggers a search query for that specific term. The search returns documents. Critically, instead of inserting all 10 documents raw, the model analyzes each for relevance: it extracts the 2-3 sentences most pertinent to the current reasoning step and inserts only those into the next prompt. This targeted refinement loop repeats—after finding the correct chemical structure definition and integrating it step-by-step, the agent arrives at the correct answer of 10 carbon atoms.

On GPQA multi-hop chemistry questions, Search-o1 achieves accuracy within competitive range of human experts by iterating 3-5 times, each time fetching and refining one piece of knowledge.

One Level Deeper

Deep research agents execute a loop: State = {query, reasoning_buffer, search_history}. At each step, the model generates tokens including its current reasoning. A language monitor detects uncertainty markers ('perhaps', 'alternatively', 'likely', 'wait') or explicit <search> tokens. When triggered, the agent generates a search query q_t and retrieves documents D_t = {d_1, ..., d_k}.

Instead of raw insertion, an extraction step computes relevance scores: for each document d_i, extract the sub-span that maximizes alignment with the current reasoning context. This extraction can be done via span selection, summary generation, or question-answering: 'Which part of this document answers my knowledge gap?' The extracted snippet e_i is inserted into State.reasoning_buffer. The model then continues generation conditioned on e_i, producing new reasoning tokens that may trigger another search or converge to a final answer.

The key mechanical object is the relevance function f_relevance(document, context) that filters noise: documents with high relevance to the current line of reasoning are kept; those with spurious matches are discarded. This prevents context bloat (the failure mode of naive RAG) and ensures each search strictly tightens the reasoning chain.

Failure Boundary

Deep research agents fail when knowledge gaps cannot be resolved through external search. If the query requires real-time data (stock prices from this hour), static document retrieval cannot help. The approach also fails when the search tool itself is poor: if retrieval returns irrelevant or misleading documents (e.g., a Wikipedia page for the wrong sense of a homonym), the extraction step amplifies noise.

The uncertainty detector (looking for 'perhaps' or <search> tokens) can miss genuine knowledge gaps if the model is overconfident and generates no uncertainty markers—in such cases, wrong reasoning propagates undetected. Additionally, the method assumes that iterative search refines toward truth, but in adversarial or ambiguous domains, each search may introduce contradictory information. If documents d_i and d_j provide conflicting definitions, the model must arbitrate this conflict, a task it may not handle well.

The extraction module requires the model to accurately identify relevant spans, but models often fail at selective reading and extract overly long or off-topic passages. If the number of search iterations is unbounded, the agent may enter infinite loops, repeatedly querying for the same information without convergence. Finally, the approach breaks on problems requiring synthesis of many sources: if the answer depends on combining insights from 20 papers, each search gives narrow context-window view, and integration across all sources is lost.

The Self-Improvement Loop

The self-improvement loop is the course's central mechanism: generate attempts, get feedback, verify or reward them, and use that signal to improve the next attempt or future model.

Read the deep dive — seen on a real run →

Ordinary Problem

Agents will make mistakes; the question is whether those mistakes create information that improves future behavior.

Naive Picture

Self-improvement means the model simply reflects on its own answer.

Why It Fails

Reflection without an external or calibrated signal can become cosmetic rewriting.

First-Principles Move

Improvement requires a feedback channel. The loop needs a generator, an environment or verifier, a scoring signal, and a policy for retrying, updating, or training.

What Breaks Without It

The system either repeats failures or optimizes for looking corrected rather than being corrected.

Course Role

The final lecture explicitly names verifiers, rewards, RL, and search as the fundamental loop.

Worked Example

A math reasoning model is improved via the self-improvement loop over 4 iterations. Starting accuracy on a benchmark of 100 problems: 40%. Iteration 1: Sample 5 solutions per problem, verify correctness, select only correct solutions for fine-tuning. After 1 epoch of supervised fine-tuning on these 40 correct examples (40% of 100), new accuracy on the same benchmark: 48%. Iteration 2: Sample again, now collect 45 correct solutions (more are found because the model is better), fine-tune. Accuracy climbs to 54%.

Iteration 3: Collect 52 correct solutions, fine-tune. Accuracy reaches 58%. Iteration 4: Collect 58 correct solutions, but fine-tuning produces only marginal gain: 59%. The plateau at iteration 4 reveals a key failure mode: diversity exhaustion—the single model generates similar reasoning chains even when sampling, so improvement slows after a few iterations. The loop shows the core mechanism: more samples reveal correct answers that were latent in the model's output distribution, feedback (correct/incorrect labels) ranks them, and training on high-confidence correct trajectories shifts the model's behavior.

With multiple specialized generator models (not just one model sampling), the diversity does not collapse. When researchers used 3 specialized models and trained them iteratively with critique, the embedding dissimilarity of their outputs remained high across 10+ iterations, and accuracy continued climbing past the plateau that the single-model approach hit at iteration 4.

One Level Deeper

The self-improvement loop is defined by four components: (1) Generator: the model proposes candidate solutions; (2) Environment/Verifier: produces a reward signal (correct/incorrect, score, error message); (3) Filter: selects high-reward candidates; (4) Policy update: trains the model on filtered data. The feedback flow is: Generator produces trajectory τ = [step1, step2, ..., stepN] → Verifier scores R(τ) ∈ {0,1} or R(τ) ∈ [0,1] → Filter returns τ if R(τ) > threshold → Update parameters θ := θ + Δθ based on {τ : R(τ) > threshold}.

The score R(τ) must be well-calibrated: if the verifier over-rewards incorrect solutions, the model learns spurious patterns; if it under-rewards correct solutions that are stylistically different, diversity collapses. The iteration count k controls the loop depth. Early iterations show sharp gains because the model has never been exposed to correct examples. Later iterations show diminishing returns due to diversity depletion: the model's sampling distribution becomes narrower, generating the same few solutions repeatedly.

The quality-vs-diversity trade-off is unavoidable—stronger verifiers accept only perfect solutions but the generator cannot produce more perfect solutions without already being better. Meta-verification (a verifier that checks the verifier's work) can reduce hallucinated errors where the original verifier falsely accepts wrong solutions. Process reward models (scorers of intermediate reasoning steps, not just final answers) provide denser feedback and help the generator learn not just to find correct answers but to reason correctly.

Failure Boundary

The self-improvement loop collapses when the verifier becomes unreliable or misaligned with the true objective. If the verifier rewards solutions that look correct but are fundamentally wrong (reward hacking), the model learns to fool the verifier rather than solve the underlying problem. This is insidious because the model's accuracy on the benchmark may rise while its true capability stays flat or falls.

The loop also stalls due to diversity collapse: after a few iterations of fine-tuning on the same model, the generator learns to produce very similar solutions, all of which either pass or fail the verifier identically. This is especially acute when using a single model for both generation and fine-tuning—after 3-5 iterations, the model's output distribution contracts and new correct solutions disappear, even if they exist in the original pre-trained distribution. Another critical failure is goal misalignment: if the verifier measures a proxy for the true goal (e.g., test-set accuracy instead of real-world safety), the loop will optimize the proxy and degrade true performance.

Catastrophic failure occurs when the loop enters a positive feedback cycle for the wrong behavior: a small initial verifier error reinforces a bad solution, which the model learns, which then produces more of that bad solution, which reinforces the error further. Finally, if the verifier is too strict, no solutions pass and no learning occurs; if it is too lenient, all solutions pass and the model stops improving. The loop requires careful calibration to stay in the productive region where some solutions pass (to learn from) but not all (to maintain a learning signal).

Verifiers

A verifier is a checker — it looks at an answer the model produces and says yes or no (right or wrong). Think of it like a test that tells you if the model's guess actually works. The verifier can be a rule written by hand, code you run to check the answer, or another AI system acting as a judge.

First Principles

When a model tries to solve a hard problem, it often tries many different paths. A verifier is the gate that looks at each try and decides which ones are actually good. Those good attempts then become the examples the model learns from. Without a verifier, the model has no way to know which of its own guesses to learn from — it just learns from noise. So the verifier is what turns wild guessing into actual learning.

Concrete Example

If a model writes code, a verifier can run that code — if it produces the right output, the verifier says yes. If a model solves a math proof, a verifier can check the logic step by step. If a model writes a support reply, a verifier can check if it follows the company's policies. In each case, the verifier is answering one question: does this actually work?

Why It Matters

A verifier is the bridge between trying many things and learning from the best tries. Without it, you could generate a million answers and have no way to tell good ones from bad ones. With a verifier, you can spot the winners and train the model to do more of what works. This is how reasoning models learn to think better — not by luck, but by repeated cycles of trying and checking.

Common Misunderstanding

Many people think that if you use another AI system as a verifier (an 'LLM judge'), it will always be right. But AI judges make mistakes too. They need testing against cases you know the answer to, backup checks for hard cases, and ways to fall back to a different method if the judge fails. An AI verifier is useful, but only if you build in safeguards to catch when it is wrong.

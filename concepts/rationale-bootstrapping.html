Rationale Bootstrapping

Rationale bootstrapping uses generated or curated explanations to help a model learn better reasoning behavior.

Read the deep dive — seen on a real run →

Ordinary Problem

You may have answers but not enough high-quality explanations showing how to reach them.

Naive Picture

Only final-answer examples are needed for reasoning tasks.

Why It Fails

For hard reasoning, the path matters. A model trained only on answers may not learn the intermediate structure.

First-Principles Move

A rationale is process data. If it is verified or filtered, it can teach the model the shape of successful reasoning.

What Breaks Without It

The model learns answer patterns without learning the method.

Course Role

Part 6 introduces STaR and rationales as train-time reasoning improvement methods.

Worked Example

STaR starts with a small seed of 100 examples that have questions, rationales, and answers. On GSM8K (9k samples), the algorithm samples 10k problems with reasoning and filters to keep only the ones with correct final answers. For incorrect answers, it provides the correct answer as a hint and asks the model to generate rationales, creating 70-87% of the data through this backward rationalization.

After fine-tuning on this curated set, the model's accuracy improves from baseline 59% to 64% on CommonsenseQA by bootstrapping iteratively: in the first iteration 3,200 correct rationales are kept, then 2,800 more are generated via hints. The model then re-trains and the next iteration captures problems it previously failed on.

Results show that direct fine-tuning needs full dataset but STaR reaches 72.5% accuracy using only 86% of the data.

One Level Deeper

STaR uses an off-policy reinforcement learning approach where the core mechanism is a correctness filter on final answers, treating successful outputs as a proxy for reasoning quality. The algorithm maintains two parallel data streams: (1) forward pass where the model generates rationale and answer on problems and keeps only the (rationale, answer) pairs where the final answer matches ground truth; (2) backward pass where for failed attempts the model is given the correct answer as a hint and asked to generate rationale, creating (hint, generated_rationale, answer) triples.

The filter r(x,y) = 1 if final answer is correct, else 0 is deterministic and binary. The key assumption is that if output correctness implies reasoning quality (which holds in domains like math where structure is constrained), then filtered rationales provide safer training signal than learning from incorrect reasoning chains. Each iteration retrains on accumulated correct rationales and hints-generated ones, and the coverage metric tracks percentage of problems with at least one correct solution discovered.

Failure Boundary

STaR's performance is fundamentally bounded by the base model's ability to reason when given answer hints. If a problem is too difficult for the model to rationalize backward (even when shown the answer), the backward pass generates invalid reasoning chains that corrupt training data. The algorithm assumes correctness of final answer implies correctness of intermediate steps, but this breaks in domains with multiple solution paths or where one step's error cascades without visible impact until the end.

In GSM8K, STaR showed minimal gains over direct fine-tuning because the problems were already within the base model's capability range—forcing additional reasoning didn't help. The method plateaus after a few iterations of the outer loop because re-sampling from a slightly-improved model still generates many incorrect outputs, and the reward signal becomes sparse when the model can't be guided backward.

Additionally, there is no filtering mechanism within step three to verify intermediate reasoning is sound, only that the final answer is correct, so it will learn spurious correlations between wrong rationales and right answers.

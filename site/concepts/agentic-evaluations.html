Agentic Evaluations

Agentic evaluations test systems that act over time, use tools, manage state, and recover from failures.

Ordinary Problem

A single QA metric does not show whether an agent can complete a real workflow.

Naive Picture

Evaluate each LLM response independently, as if every message were a standalone answer.

Why It Fails

Agent failures happen across steps: wrong tool call, lost state, repeated loop, weak recovery, or premature stopping.

First-Principles Move

The evaluation unit should match the task unit. For agents, that unit is often a trajectory or completed workflow, not a single message.

What Breaks Without It

Benchmarks overstate capability because they miss long-horizon failure modes.

Course Role

Part 8 focuses on this evaluation shift from isolated answers to trajectories and long-horizon workflows.

Worked Example

A coding agent is evaluated on the METR benchmark. The task is to refactor a codebase, which typically takes a professional 2-4 hours. The system generates a complete plan, applies code changes, runs tests, and detects failures. In three independent runs, the agent completes the refactoring with success rates of 40%, 35%, and 55%. The evaluation aggregates across multiple tasks: on short tasks (1-30 seconds), the model succeeds 78% of the time; on medium tasks (1-30 minutes), success rates drop to variable levels (0% to 80%); on research engineering tasks (up to 8 hours), success falls below 20%.

A single metric like "did the refactoring work" misses the failure distribution. Instead, trajectory-based metrics show that the agent completed the task 43% of the time on average. The benchmark tracks how long a task typically takes a human professional (calibrated against 5+ years of experience) and measures whether the model can complete it within that time. For GPT-2 (2019), models could only handle 2-second tasks. By 2023 (GPT-4), the capability had grown to 8-minute tasks. Current frontier models (Claude 3.5, o1) complete 59-minute tasks at 50% reliability, doubling approximately every 7 months.

One Level Deeper

Agentic evaluation measures a complete workflow trajectory, not isolated responses. The evaluation unit is the task completion rate—the percentage of end-to-end attempts that reach a successful final state. For METR, this is computed as: (number of successful task runs) / (total task runs attempted) per time-horizon bracket. The success criteria include both functional correctness and the number of intermediate steps required. A failure can occur at any step: incorrect tool choice at step 2, reasoning error at step 5, or inability to recover after step 7.

The metric also tracks two reliability thresholds: the 50% success horizon and the 80% success horizon. A large gap between them (e.g., 59 minutes at 50% success vs. 15 minutes at 80%) reveals where systematic error recovery is weak. Current models show this gap clearly: they can attempt longer tasks, but only rarely complete them reliably. This gap is the frontier of research—bridging the 44-minute reliability gap from 50% to 80% success is the next generation's challenge.

Failure Boundary

Agentic evaluations break down when the task requires dynamic adaptation beyond the agent's capabilities. If an agent enters a repetitive loop—attempting the same action repeatedly despite failures—it will never reach task completion, yet single-response metrics would not flag this. The agent may also fail due to state loss: forgetting the original goal after multiple tool calls, or misremembering previous attempts. These failure modes compound over long horizons but are invisible in snapshot evaluations.

Evaluations also saturate and lose discriminative power when tasks become too well-specified or too artificially constrained; real-world tasks require figuring out what to work on, not just executing a fully specified plan. If the evaluation environment is adversarial or messy (multiple valid solutions, subjective acceptance criteria), simple pass/fail metrics become unreliable because human graders disagree. The evaluation itself is only as honest as its stopping condition: if the agent is allowed infinite retries, even a weak agent can appear capable. Finally, the benchmark loses relevance if the test distribution drifts from real deployment scenarios—this is why live benchmarks (updated monthly with new papers) are more trustworthy than static ones.

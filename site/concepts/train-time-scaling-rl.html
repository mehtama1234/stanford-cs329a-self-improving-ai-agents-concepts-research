Train-Time Scaling With RL

Train-time scaling improves the model itself using rationales, rewards, verifiers, and reinforcement learning instead of only spending more compute at inference.

Read the deep dive — seen on a real run →

Ordinary Problem

Inference tricks can help a fixed model, but you may want the model's default behavior to improve over time.

Naive Picture

Self-improvement only happens during runtime search after the model has already been trained.

Why It Fails

Runtime successes and verifier feedback can become training data or rewards that change future model behavior.

First-Principles Move

Feedback can be used in two places: at inference to select an answer, or during training to shift the model's policy toward better reasoning trajectories.

What Breaks Without It

You repeatedly pay for the same correction at inference time instead of teaching the model to avoid it.

Course Role

Part 6 connects reasoning rationales, DeepSeek-style math training, and RL for long chains.

Worked Example

A 7B model (DeepSeekMath) starts with 46.8% accuracy on the Math benchmark. Step 1: Supervised fine-tuning on domain data. The model is trained on curated math web pages from OpenWebMath (higher coverage than arXiv alone), supplemented with code-like reasoning patterns from pretraining. After SFT, accuracy improves to ~49%. Step 2: RL training with GRPO. For each of 200 AIME problems, sample 64 candidate solutions. Score each solution with a trained reward model: correct solutions get R = 1.0, incorrect get R = 0 to 0.3 (depending on partial credit from a process reward model). Compute group-relative advantage: A(i) = (R(i) - mean(R)) / std(R). This normalizes the reward distribution per problem. Update policy: ∇log π(solution_i | problem) weighted by A(i). After 50 iterations of RL, accuracy reaches 51.7%. The model has learned to reason more reliably, with 70–87% of generated solutions now producing correct answers (pass@K improved across K = 1, 2, 4). Contrast: a model using naive sampling without RL optimization would still be stuck near the SFT baseline (~49%), showing no improvement.

One Level Deeper

Train-time scaling RL closes a feedback loop: (1) A base policy π_old generates trajectories; (2) a reward model R(τ) scores each (problem, solution) trajectory on correctness; (3) advantage is computed using group-relative comparisons A(i) = (R(i) - μ_R) / σ_R, avoiding the need for a separate critic network (memory-efficient); (4) policy gradient updates shift probability mass toward high-advantage trajectories: ∇J = E[∇log π(a | s) * A]. Key implementation details: (a) GRPO uses normalization per batch of problems rather than per-token, reducing variance. (b) KL divergence penalty ‖π(·|s) - π_old(·|s)‖_KL is applied to prevent the policy from diverging too far from its prior behavior (preventing reward hacking and catastrophic forgetting of already-learned skills). (c) For long reasoning chains, entropy shaping and token-level loss are used: if response length explodes or entropy collapses, apply penalties to stabilize exploration. (d) Dynamic sampling filters out all-correct and all-wrong batches to maintain an effective gradient signal (avoiding near-zero advantages when all samples succeed or all fail).

Failure Boundary

Train-time scaling RL becomes unreliable when (a) the reward model saturates or is miscalibrated—if nearly all generated solutions score identically (all high or all low), advantage A(i) → 0, and gradient flow vanishes. The model learns nothing. Early detection: monitor whether accuracy is improving; if accuracy plateaus but RL continues, the reward model is likely exhausted. (b) The base model lacks foundational capability—if the model cannot solve any problems in the training set, no positive reward signal exists, and the RL loop has nothing to optimize toward. STaR-style rationalization (backward reasoning from hints) can partially mitigate but requires the model to reason about correct answers, not discover new solutions. (c) Entropy collapse—the model becomes overconfident, concentrating probability on a single solution per problem, losing exploration. This also manifests as response length explosion (reasoning chains grow unbounded) if not controlled via token-level penalties. (d) Distribution shift—if the RL reward model was trained on one class of problems (e.g., AIME), but is applied to a different distribution (e.g., GSM8K), the reward signal may be misleading. Finally, RL does not improve pass@1 (single-attempt accuracy) beyond what majority voting provides unless the underlying capability boundary shifts; empirically, RL improves majority@K but rarely teaches fundamentally new problem-solving strategies, only more reliable execution of existing knowledge.

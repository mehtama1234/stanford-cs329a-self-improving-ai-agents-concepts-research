Planning As Search

Planning as search treats an agent's future as a tree or graph of possible thoughts, actions, observations, and next states.

Ordinary Problem

The first plan may be wrong, and many possible next actions compete for attention.

Naive Picture

Generate one complete plan from start to finish and then follow it.

Why It Fails

Long tasks need branching, backtracking, and updating as information arrives.

First-Principles Move

Planning chooses among possible trajectories. Search lets the agent explore alternatives, score partial paths, and commit only after enough evidence.

What Breaks Without It

The agent becomes brittle: one early bad choice corrupts the rest of the task.

Course Role

Part 5 centers this through Language Agent Tree Search.

Worked Example

A task is to plan a trip to Hawaii. The initial state is: "You want to plan a Hawaii trip, budget is $5000, 7 days." At the root, the model samples 3 candidate first actions: (1) ask friends about Hawaii, (2) search travel blogs, (3) check flight prices. Each action is scored: action 1 receives an LLM-as-a-Judge score of 0.8 (very promising) and a self-consistency score of 0.75 (75% of 50 samples were variations of "ask friends"), combined into V(action_1) ≈ 0.78. Actions 2 and 3 score lower (0.5 and 0.4). Using UCT (which balances exploitation V(s) + exploration √(log(N_parent)/N_state)), the system expands action 1 (ask two specific friends). Friend A suggests budget resort in Maui, Friend B suggests Kona snorkeling. This observation updates the context. The system continues branching from the highest-scoring node until reaching a terminal state (booking confirmation) or exhausting depth, then backpropagates the final outcome (success/failure) to update all ancestor node values.

One Level Deeper

Planning as search builds a tree where each node represents a state (goal + observations so far), each edge an action sampled by the language model. The search uses Monte Carlo Tree Search (MCTS) with four components: (1) Selection via UCT = V(s) + C * √(log(N_parent) / N_child), where N tracks visit counts, balancing high-value nodes (exploitation) against under-explored siblings (exploration). (2) Expansion: the model generates K candidate actions from the selected node. (3) Evaluation: each child is scored using a value function V̂(s) = α * LLM_judge_score(s) + (1-α) * self_consistency(s), where self-consistency counts how many of K samples propose similar actions. (4) Backpropagation: final trajectory outcome R (1 if success, 0 if failure) propagates backward, updating V_new(s) = (V_old(s) * visits(s) + R) / (visits(s) + 1). Reflection (optional) adds model critique: after each trajectory, the model generates explanatory text about why it succeeded or failed, which is stored with the trajectory.

Failure Boundary

Planning as search becomes unreliable when (a) the state space is too large or the horizon too deep—the tree expands exponentially and the system cannot afford enough samples to explore meaningfully, leading to high-variance node value estimates and poor decisions. (b) The LLM judge score is miscalibrated or adversarial—if the judge assigns high scores to promising-sounding but ultimately incorrect paths, the system wastes computation on dead ends (e.g., scoring "book expensive last-minute flight" as promising when it violates the budget constraint). (c) Actions are irreversible—if an action in the real world has consequences (booking a hotel, purchasing a ticket), the model's exploration during training/search can cause real harm or waste money; the tree search assumes the ability to backtrack or retry. (d) The observation model is noisy—if actions return stochastic or misleading feedback (simulated environment reports success when the plan is actually flawed), the backpropagated rewards corrupt the value estimates across the tree.

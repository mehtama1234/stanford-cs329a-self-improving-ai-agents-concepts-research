The self-improvement loop — when an error creates the information to fix it

Agents make mistakes. The question is whether each mistake becomes information that improves the next attempt. Here is the loop: answer, look at your own answer, revise it, repeat. A real run on a small model over three rounds showed mistakes being caught and corrected, accuracy climbing from 42% to 58%, and a simple pattern: every fix that changed an answer made it better. This is where reinforcement learning, verifiers, and tool-using agents all begin.

1 · The problem — one shot wastes the mistake

Ask a model a hard math question once. It writes out steps, reaches an answer, and stops. If that chain of reasoning took a wrong turn, the whole answer is wrong. The model probably knew how to reason correctly — it just went down a bad path. But the human who sent the message sees only the answer, not the path inside the model's head. The mistake vanishes. Nothing is learned from being wrong.

So the honest question is: how do I give the model a chance to see its own error and correct it?

2 · The reframe — close the loop: answer, critique, revise, repeat

Instead of stopping after one answer, ask the model to look back at what it wrote and check it. Ask: is this answer correct? Did I make a mistake? What should I fix? Then give it a chance to write a revised answer. And do it again — one more round of critique and revision.

This closes a feedback loop inside the model itself. The first answer creates an error. The critique (ideally) notices the error. The revision fixes it. No new training. No new data. Just: take the first answer, feed it back in, and let the model try again. This is called self-refinement or self-refine, and the loop it closes is the seed of everything that follows — verifiers, reinforcement learning, planning, agent loops with tools.

3 · Seen on a real run — mistakes corrected, accuracy climbs from 42% to 58%

We ran a real 0.6-billion-parameter model (Qwen3-0.6B — small on purpose, so it makes genuine errors) on 12 grade-school math word problems. We had it answer once, then critique-and-revise, then critique-and-revise again, over three rounds total. Every number here is measured.

round 1 (first answer)5 / 12 = 42%5 correct

The discovered fact: when a model critiques its own work and revises, it catches mistakes. Over three rounds, it gained 2 correct answers, and every revision that changed an answer improved it — fixed 1, broke 0 in round 1; fixed 1, broke 0 in round 2. Total: 2 fixed, 0 broken. The loop was strictly positive here. It did not fix all the mistakes — 5 stayed wrong all three rounds — but of the ones it touched, it touched only to correct.

4 · Why the loop can climb — and why it often does

The model that made the first mistake is the same model doing the critique. So why does it catch the error the second time? Because the first answer is now a fact in front of the model, concrete and visible. The model can read its own work. When it reads 'I said the answer is 47' and then works through the problem again to check, it may see the contradiction. The first attempt leaves a footprint, and critique means walking over that footprint and looking carefully.

This works when the model can actually see its own error — when its self-criticism is honest. On this run, it often could. The model spotted three kinds of mistakes: arithmetic errors (it added wrong), logical mis-steps (it forgot a constraint in the problem), and interpretation flips (it read the problem backwards). Once it saw these, it revised and got the right answer.

5 · The one real weakness — self-critique is only as good as the model's own judgment

If the model cannot tell right from wrong, the loop breaks. The model might critique a correct answer and convince itself it is wrong, then 'fix' it into a mistake. This is called self-reinforcing error. It can also fail to see a genuine mistake and write the same wrong answer again and again, each time convinced it is right. On this run, the model happened to be honest — it did not break a single correct answer — but that is not guaranteed. Honesty is fragile and depends on the model's size, training, and the specific domain.

The loop also stalls if the model is stuck. If the first answer leads into a conceptual dead-end — the model genuinely cannot think its way out — critique alone won't help. It will re-read the mistake, but re-reasoning from scratch may just lead to the same dead-end again. On 5 of the 12 problems, this is what happened: the model stayed wrong all three rounds.

6 · The surprise — this loop reappears in every method that follows

Add a verifier to the loop — an external checker that labels which answers are right and which are wrong — and now the model trains on its mistakes instead of just revising them. That is supervised learning from mistakes. Add a reward signal (give more reward to correct answers), and the loop becomes reinforcement learning. Give the model access to tools like a calculator or a code runner, and it can verify its own work before finalizing the answer. That is the tool-using agent loop.

Every heavier method — every RL trick, every planning algorithm, every agent architecture with feedback — is built on this one core piece: answer, check if the answer is right (by critique, by verification, by reward, by the outside world), and use that signal to improve. The self-improvement loop is not an algorithm. It is the shape of learning itself.

7 · Where it is used in practice — Answer, critique your work, revise—close the feedback loop

Self-refinement appears in every system that gives agents feedback: a model answers a question, is prompted to critique and revise the answer, and repeats. Tool-using agents (with calculators, code runners, search) use this loop to verify their work before finalizing. Reinforcement-learning-trained reasoning models optimize this loop by rewarding correct revisions and penalizing bad ones. Even simple local systems use it: answer, check, try again. The loop is the seed of everything: verifiers are external critics, reinforcement learning adds rewards, and planning agents scaffold the loop with tools.

The model makes a first attempt, then reads its own work and decides whether it is right. If it detects an error, it revises. No external training signal, no new data—just feedback from the model to itself. Each revision that corrects a mistake teaches the model that self-critique works. If the model catches the error and fixes it on the second pass, the loop succeeded. The loop is closed because the output of one step (an incorrect answer) becomes the input to the next step (the critique).

Self-critique is only as good as the model's own judgment: if the model cannot tell right from wrong, it may break correct answers while revising, or stay stuck repeating the same mistake.

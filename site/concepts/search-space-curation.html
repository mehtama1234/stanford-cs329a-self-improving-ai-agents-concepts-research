Search-Space Curation

Search-space curation is the work of sampling many possible outputs and filtering, clustering, testing, or ranking them into a final answer.

Ordinary Problem

The model's output space may contain good solutions, but most samples may be redundant, weak, or wrong.

Naive Picture

If the right answer is somewhere in the samples, we are done.

Why It Fails

A large candidate set still requires deduplication, selection, verification, and sometimes diversity control.

First-Principles Move

Search creates raw possibility. Curation turns possibility into a usable decision by imposing tests and selection criteria.

What Breaks Without It

The system drowns in candidates and cannot reliably extract the correct one.

Course Role

Part 7 uses AlphaCode-style systems to make this concrete.

Worked Example

AlphaCode generates 1 million diverse code solutions per competitive programming problem by sampling from a trained model at high temperature with randomized problem tags. From 1 million samples, the curation pipeline filters out 95%, leaving ~50,000 candidates that pass the example test cases provided in the problem statement. Then clustering using syntactic+semantic equivalence further reduces to ~10,000 groups.

When submitting to the Codeforces platform, only 10 solutions are allowed per problem. Using the 41B AlphaCode model with clustering, at 10@1k (10 submissions from 1000 samples) achieved 22% solve rate on validation. At 10@1 million (10 best from all 1 million), this improved to 30%. AlphaCode 2 improved the base model and added a learned scoring function (reward model), achieving the same 30% solve rate with only 10@100 samples—a 10,000x reduction in needed sampling, because better curation and model quality reduced redundancy.

One Level Deeper

Search-space curation applies a multi-stage filtering pipeline with selection criteria Score(candidate_i) that rank candidates. Stage 1 is execution filtering: run each sample against provided test cases, keep only those that compile and pass. Stage 2 is deduplication via clustering: group semantically equivalent solutions using a learned test-input generation model that predicts likely test cases for unseen problems, then cluster solutions by whether they produce identical outputs on generated tests.

Stage 3 is reranking via learned scoring: train a reward model r(code_sample) ∈ [0,1] on held-out high-quality solutions to predict correctness. The selection rule is: keep top-k solutions by score r(·), break ties by solution length or cluster size. The key algorithmic insight is that pass@k (unlimited attempts) differs from 10@k (submit 10): between these bounds lies selection loss L_select = pass@k - 10@k, the gap caused by imperfect curation.

Improved selection (better scoring, better clustering) directly reduces this gap. The log-linear trend pass@k ∝ k^α (α ≈ 0.5 for competitive code) persists even after selection, showing that with sufficient sampling and good curation, coverage remains strong.

Failure Boundary

Search-space curation saturates when the candidate set stops improving with more samples. If 1 million samples are generated but most are variants of a small set of solution approaches (low diversity), filtering cannot recover solutions that don't exist in the search space. In domains like dynamic programming, AlphaCode found that the search space itself was limited—many problems simply had fewer fundamentally different solution approaches the model could generate.

The curation quality depends on the verifier (does the test case execution correctly validate solutions?): if test execution is incomplete or incorrect, many invalid solutions pass through to later stages. The scoring model r(·) is trained on a limited dataset and can be gamed: if training data skews toward a particular solution style, the scoring model rewards similar solutions even if they fail on unseen test cases. Clustering by semantic equivalence requires defining what 'equivalent' means—this is expensive and domain-specific.

In novel problem types, the clustering heuristic breaks because there are no patterns to cluster on. Additionally, the approach generates massive computational waste: 95% of samples are filtered out. In time-bounded settings (where latency matters more than accuracy), generating 1 million samples is impractical even if curation works perfectly. Finally, the method fails out-of-distribution: test cases generated for known problems don't generalize to novel problem structures, so clustering and equivalence checking become unreliable.

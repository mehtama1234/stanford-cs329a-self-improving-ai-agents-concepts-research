ReAct: Reason, Act, Observe

ReAct is a pattern where the model alternates between thinking about what to do, taking an action, observing the result, and continuing.

Ordinary Problem

A multi-step task needs both reasoning and new information from actions.

Naive Picture

Reasoning and acting are separate phases that can be planned once and then executed.

Why It Fails

Actions change what the model knows. Reasoning must adapt after every observation.

First-Principles Move

The agent's state is updated by observations. A good next action depends on both the original goal and the latest observed result.

What Breaks Without It

The model plans blindly and fails to revise when the environment responds differently than expected.

Course Role

Part 4 presents ReAct as an early tool-augmented agent pattern.

Worked Example

Question: "Aside from the Apple remote, what other device can control the program Apple remote was originally designed to interact with?" This is a multi-hop retrieval task.

Reason (thought 1): "I need to find out what Apple remote was originally designed to control." Act (search): Query Wikipedia for "Apple remote". Observation: "Apple remote is a remote control introduced in 2005, designed to control Front Row media center." Reason (thought 2): "Now I need to find what else controls Front Row." Act (search): Query Wikipedia for "Front Row". Observation: "Front Row is a discontinued media software center by Apple." Reason (thought 3): "Front Row is discontinued, so I should check what it competed with or what devices used it." Act (search): Query "Front Row compatible devices". Observation returns information showing Front Row was part of Mac systems, but another media center also worked with it. Final answer emerges from chained reasoning + observations.

Without ReAct (pure Chain-of-Thought), the model would reason internally but produce wrong intermediate conclusions because it has no real-world grounding. With ReAct, each reasoning step is informed by actual retrieved data, so the chain stays anchored.

One Level Deeper

ReAct implements a loop: s_t = (goal, observations_1...t, reasoning_1...t). At step t, the model outputs: (thought_t, action_t). The thought is textual reasoning; the action is a tool call. The environment executes action_t and returns observation_t. Then s_{t+1} = (goal, observations_1...t, reasoning_1...t, thought_t, action_t, observation_t). The model continues.

Formally, thought_t = LM(s_t, prompt="Reason:"), action_t = LM(s_t + thought_t, prompt="Action:"). After each observation, the context window grows: s_{t+1} = s_t + (thought_t, action_t, observation_t). This is interleaved reasoning and action, not sequential (all reasoning then all actions). The key is that observation_t updates the state before thought_{t+1} is generated, ensuring the next reasoning depends on what was just learned. Empirically, this interleaving outperforms generating a full plan upfront because the model can adapt when observations surprise it.

Failure Boundary

ReAct fails when observations are noisy or contradictory. For example, if a search returns misleading information (stale Wikipedia, fake results), the model may reason correctly from false premises. Thought 1: "According to this source, X is true." But X is false. Thought 2 then builds on the falsehood. You observe: coherent reasoning traces, but wrong final answers. The model was confident but guided by bad observations.

Another failure: error compounding. At step t, the model makes a reasoning mistake (e.g., misinterprets an observation). At step t+1, it acts on the wrong interpretation. At step t+2, it has invested in a dead-end path. Without backtracking or replay mechanisms, the model may loop (e.g., searching the same query repeatedly with minor variations) or get stuck. The trace becomes repetitive and fails to reach the goal. Mitigation requires: (1) confidence scoring on observations—if an observation seems implausible, reject it or search for confirmation, (2) planning bounds—stop if stuck after N steps, (3) backtracking—detect failed branches and try alternatives. Without these, ReAct-based agents can fail worse than simple Chain-of-Thought because they invest compute in wrong paths anchored to false observations.

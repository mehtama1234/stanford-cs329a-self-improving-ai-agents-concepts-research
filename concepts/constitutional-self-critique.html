Constitutional Self-Critique

Constitutional self-critique uses model-generated critique against a set of principles to improve or filter outputs.

Ordinary Problem

Some tasks do not have a simple executable test, but still need feedback about quality, safety, or policy alignment.

Naive Picture

Only humans can provide useful preference or critique data.

Why It Fails

Human feedback is expensive and slow; model critique can scale certain forms of review when grounded by a rubric.

First-Principles Move

A principle set acts like a soft verifier. It cannot prove correctness, but it can create structured feedback when objective checks are unavailable.

What Breaks Without It

The system lacks scalable feedback for subjective or policy-heavy outputs.

Course Role

Part 4 includes constitutional AI as a feedback method alongside tool and execution feedback.

Worked Example

A base model is given a red-teaming prompt asking it to write a product recommendation. It generates a response that subtly exhibits gender bias (e.g., assumes a caregiver role preference for women). The system then applies a constitutional critique: it prompts the model with the original output and asks "Does this response contain gender bias? If so, what is it?" The model critiques itself and identifies the bias. Next, a revision request: "Rewrite this response removing any trace of gender bias." The model produces a revised version. This critique-and-revision pair (original → critique → revision) becomes a supervised fine-tuning example. After fine-tuning on hundreds of such traces, the model improves at following the constitution. Then an RL stage trains a preference model on pairs of (original, revised) outputs, where the preference model learns that revised > original. Finally, the base policy is aligned to maximize this preference model score, pushing the model toward more constitutional outputs.

One Level Deeper

Constitutional self-critique uses the language model as both a critic and a reviser, implementing a soft verifier that operates without external labels. The process has two stages: (1) Supervised Fine-Tuning: the model fine-tunes on (problem, critique, revision) triplets, where critique R and revision R' are generated by the model itself following a human-written principle set (the "Constitution"). The loss is standard cross-entropy on R and R'. (2) RL Stage: a preference model π_pref(R' > R | problem) is trained using AI feedback from the constitution as ground truth, then the policy is optimized via PPO or similar to maximize E[π_pref(revision > original)]. Crucially, the constitution acts as a composable rubric—principles can address harmlessness, honesty, or helpfulness independently, and the preference model learns to rank candidate outputs by how well they satisfy all principles together.

Failure Boundary

Constitutional self-critique fails when the model cannot reliably apply the principles, either because (a) the principles are too vague or contradictory (e.g., "be helpful" vs. "never offend" can conflict), causing the model to confabulate critique rather than detect real issues, or (b) the model is overconfident and rationalizes errors as correct behavior, effectively learning to produce convincing-but-false self-critique. If the preference model is trained only on AI feedback and never calibrated against human preferences, it may diverge: the model learns to game the constitutional scoring function rather than genuinely improve. Additionally, if the original model lacks the reasoning capability to execute the critique-and-revision loop (e.g., cannot identify bias it was trained to produce), the loop adds noise rather than signal. Finally, improvements in harmlessness can come at the cost of helpfulness if the constitution is overly restrictive; the system is constrained to the trade-off frontier implied by the chosen principles.

Algorithmic Progress Categories

Algorithmic progress is not one thing. It mixes architecture, optimizers, systems work, data improvements, distillation, long-context methods, RL, tools, and evaluation design.

First Principles

If model performance improves at fixed compute, the cause could be a better learning algorithm, better data, better implementation, better hardware utilization, better inference strategy, or a new post-training paradigm. Lumping all of these together obscures what actually changed.

Concrete Example

A newer model may beat an older model because it used better synthetic math data, not because its transformer block is fundamentally better.

Why It Matters

This matters for forecasting and engineering. The next bottleneck depends on which source of progress is actually driving gains.

Common Misunderstanding

Calling everything algorithmic progress can double-count gains and hide the role of data and systems engineering.

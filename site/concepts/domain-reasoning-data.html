Domain Reasoning Data

Domain reasoning data is targeted data from areas like math or code where reasoning steps and correctness can be checked.

Ordinary Problem

General text does not provide enough verified examples of hard reasoning.

Naive Picture

More generic internet data is enough because larger corpora should contain more reasoning examples.

Why It Fails

Reasoning-heavy domains need dense examples of structured problems, intermediate steps, and checkable answers.

First-Principles Move

The training data should contain the behavior you want the model to learn. For reasoning, that means problems, rationales, verifiers, and outcomes.

What Breaks Without It

The model imitates reasoning language without reliable reasoning skill.

Course Role

Part 6 uses DeepSeek Math as the case for math-focused reasoning training.

Worked Example

DeepSeek Math began by training a 7B model on domain-specific data instead of generic internet text. First, they started from a DeepSeek Coder model (already trained on code) rather than pre-training from scratch. Then they curated math-heavy data: instead of using archive papers which provided sparse coverage, they mined Common Crawl web pages for OpenWebMath—a dataset that contained much higher density of step-by-step math solutions across diverse domains like algebra, calculus, and proofs.

By fine-tuning the 7B base model on this curated math dataset, they achieved 46.8% on the Math benchmark. Then applying train-time scaling (GRPO with group baseline), this improved to 51.7%. The key difference: models trained on domain-specific mathematical content showed dramatic gains where generic pre-training had plateaued.

A 7B model now competed with much larger models, demonstrating how targeted data density in reasoning domains outweighs pure parameter scaling.

One Level Deeper

Domain reasoning data operates by increasing the concentration of verified problem-solution pairs with intermediate steps in the training corpus. For math domains, the data distribution shift is from generic internet tokens (where math appears sparsely and unsystematically) to explicit mathematical problem-solution sequences where each problem-step-answer triple is structured. The curation criterion is semantic relevance to the target domain: web pages containing worked math problems score high; articles with equations but no step-by-step reasoning score lower.

DeepSeek measured coverage as fraction of token budget spent on math reasoning vs. other domains. The mechanism is that during pre-training on this distribution, the model allocates representational capacity to the patterns of mathematical reasoning (problem analysis, transformation, verification) that are highly prevalent in the data. When the model sees domain-specific patterns repeatedly, it learns the implicit grammar of mathematical thought.

This is distinct from instruction tuning where human-written prompts guide behavior; domain data directly shows the model examples of correct reasoning in context.

Failure Boundary

Domain reasoning data's utility vanishes if the target domain is fundamentally outside the model's capability range or if the data lacks actual reasoning structure. Purely collecting more math problems without step-by-step solutions still yields poor reasoning—the dataset must be high-quality and structured. If you provide domain data that contains errors (incorrect solutions presented as ground truth), the model learns invalid patterns.

The approach also fails when domain concepts are too novel or require external tools; a math model trained only on paper won't learn to use a calculator or numerical solver just from seeing equations. Additionally, domain data alone doesn't generalize out-of-distribution: a model trained on STEM domains from Common Crawl won't suddenly solve novel reasoning tasks outside its training data's semantic scope.

The curation process itself becomes a bottleneck—if identifying high-quality domain data requires expensive human annotation, the scaling advantage is lost. Finally, models reach a plateau when the domain dataset becomes saturated relative to model capacity; past that point, only increasing model size or diversifying domains helps.

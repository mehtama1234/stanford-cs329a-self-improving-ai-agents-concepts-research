reinforcement learning

GRPO

GRPO is a technique that helps a reasoning model get better at solving hard problems by having it generate multiple answers to the same question, scoring each one, and then strengthening the ones that worked better than average. Think of it like taking a test five times, keeping track of which answers you got right more often than not, and learning from that contrast.

First Principles

When a model learns to reason better, it needs a signal about which attempts were actually good. Normally, you'd use a separate checker program to score each answer — that costs extra resources. GRPO cuts out that middle layer: it has the model generate several tries for one problem all at once, ranks them by whether they're correct or incorrect, and uses the gap between the good ones and bad ones as the learning nudge. The nudge says: make answers like those good ones more likely, and answers like those bad ones less likely.

Concrete Example

A reasoning model is learning to solve math problems. For one problem it generates eight different solutions in a row. Three of them compute the right answer. Five compute wrong answers. GRPO looks at that set: it sees 'these three worked, these five didn't,' and adjusts the model so that on the next try, it leans toward solutions that look more like the three that worked. The model doesn't need anyone to tell it what 'right' means — it figures it out from the natural difference between its attempts.

Why It Matters

Reasoning models need to learn to spend time thinking carefully on hard questions. Teaching them to do that usually requires complex machinery: a separate scorer, careful setup, and lots of bookkeeping. GRPO is simpler — one model, one question, a batch of tries — and it actually works because trying many times on the same problem naturally separates the good solutions from the bad ones. This simplicity is why GRPO helped make learning-to-reason affordable and fast enough for real systems.

Common Misunderstanding

A common trap: thinking GRPO learns something useful from every problem. It doesn't. If the model generates eight answers and all eight are equally correct, or all eight are equally wrong, there is no pattern to learn from — GRPO has nothing to do. The learning only happens when there's a real split: some answers work, others fail. The power comes from that difference, not just from sampling multiple attempts.

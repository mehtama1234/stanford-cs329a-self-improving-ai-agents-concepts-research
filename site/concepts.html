First-Principles Concepts

Each page starts from an ordinary problem, then explains the mathematical or systems move the lecture is building toward.

From Scaling To Reasoning

You want systems that solve harder tasks, but simply making a base model larger is expensive and eventually gives smaller practical gains.

capability

Reasoning Traces

Hard tasks require linked intermediate states. If the model jumps directly to the answer, there is little to inspect or repair.

reasoning

Test-Time Compute

A model may know how to solve a problem sometimes, but one attempt may land on a weak path.

inference

Repeated Sampling And Coverage

Some hard problems have rare correct outputs. You need a way to expose those rare successes.

inference

Inference Budgeting

More samples, deeper search, and more verifier calls can improve quality but cost time and money.

inference

The Verifier Selection Gap

A model can produce many candidates, but the system needs a trustworthy way to select one.

verification

Process Supervision

A final answer can be right for the wrong reason or wrong because of one local step.

verification

Verifier Robustness

A weak verifier can approve wrong work or reject good work, causing the whole loop to optimize the wrong signal.

verification

Tool Calling

Text-only reasoning cannot directly observe the world, run a test, query a database, or change a file.

tools

ReAct: Reason, Act, Observe

A multi-step task needs both reasoning and new information from actions.

tools

Execution Feedback

Code can look plausible while failing at runtime or producing the wrong output.

tools

Constitutional Self-Critique

Some tasks do not have a simple executable test, but still need feedback about quality, safety, or policy alignment.

feedback

Planning As Search

The first plan may be wrong, and many possible next actions compete for attention.

planning

Trajectory Optimization For Agents

A task can fail because the sequence of steps is wrong even when some individual steps look reasonable.

planning

Train-Time Scaling With RL

Inference tricks can help a fixed model, but you may want the model's default behavior to improve over time.

training

Rationale Bootstrapping

You may have answers but not enough high-quality explanations showing how to reach them.

training

Domain Reasoning Data

General text does not provide enough verified examples of hard reasoning.

training

Process Reward Models

A final reward is sparse and may arrive too late to show which step helped or hurt.

training

Search-Space Curation

The model's output space may contain good solutions, but most samples may be redundant, weak, or wrong.

search

Deep Research Agents

Research work is not one lookup. It requires source discovery, relevance filtering, synthesis, citation, and uncertainty handling.

applications

Agentic Evaluations

A single QA metric does not show whether an agent can complete a real workflow.

evaluation

Long-Horizon State And Memory

Long tasks require continuity. The agent must know what has already happened and what remains unresolved.

evaluation

The Self-Improvement Loop

Agents will make mistakes; the question is whether those mistakes create information that improves future behavior.

synthesis

Open-Ended Self-Improvement

Fixed rewards can improve known tasks but may fail to discover new tasks, strategies, or research directions.

future

The Agent Loop

Many useful tasks require doing work, not just answering a message.

agents

Workflow Orchestration

Real tasks are too large or varied for one undifferentiated model call.

systems

Task Specification

Users often underspecify what they want, what sources are allowed, or what counts as done.

reliability

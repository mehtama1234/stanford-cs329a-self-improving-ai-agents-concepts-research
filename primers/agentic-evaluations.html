Agentic Evaluations

Agentic evaluations test whether an AI system can work over many steps to finish a real task. Think of it this way: instead of asking a model one question and checking its answer, you give it a goal (like 'fix this broken code') and watch it take multiple actions — read files, run tests, try fixes, learn from failures — until the job is done. It measures whether the system can keep track of where it is, use its tools correctly, and recover when something goes wrong.

First Principles

A simple test asks one question and scores the answer right or wrong — like a quiz. An agentic test is different: it starts with a goal and watches the system over many steps. The system must remember what it is trying to do, pick the right action at each step, use a tool (read a file, run a command) correctly, notice when something failed, and try again. Success means finishing the whole job, not just giving a smart-sounding response to one prompt.

Concrete Example

A simple test says 'write me a code snippet that sorts a list.' An agentic test says 'there is a broken sorting function in a repository — find the bug, fix the code, run the test suite, and make sure all tests pass.' The system must search through files, read the error messages, change the code, re-run tests, and keep going until it actually works. A single guess is not enough.

Why It Matters

Modern AI systems are built to work like this: they think step by step (reasoning), they use tools (code, search, memory), and they learn from mistakes (feedback). A one-question test does not measure any of that. Agentic evaluations check if a system can actually do real work — keep a goal in mind, make choices, recover from errors, and finish. If you want to know whether an AI can improve itself, you need to measure whether it can handle a task that takes multiple tries and course corrections.

Common Misunderstanding

Agentic evaluation is not just writing a longer prompt or asking for more detail. It requires three things to work: the system needs memory or state (to know where it is and what it tried), access to real tools (not just text output), and a way to measure success beyond 'did it sound smart.' A test that gives the system 10 tries to answer one question is longer, but it is not agentic unless the system can use those tries to do real work — like actually running code, seeing what breaks, and fixing it.

Workflow Orchestration

Workflow orchestration is the system design around the model: chains, routers, parallel workers, managers, tools, judges, and verifiers.

Ordinary Problem

Real tasks are too large or varied for one undifferentiated model call.

Naive Picture

One large prompt should handle planning, tools, checking, and synthesis.

Why It Fails

Different subtasks need different routes, tools, budgets, and checks.

First-Principles Move

Expose the workflow structure. Once steps are explicit, they can be routed, parallelized, verified, retried, and debugged.

What Breaks Without It

The agent becomes opaque: you cannot tell where it failed or how to improve it.

Course Role

Part 1 introduces orchestration patterns that later lectures deepen.

Worked Example

A deep research workflow for "Best practices for Python code testing" orchestrates 4 parallel workers and 1 aggregator. Worker 1 searches for "unit testing frameworks Python" and generates 3 candidate sources (pytest docs, unittest guide, hypothesis property testing). Worker 2 searches for "Python test coverage tools" and generates 2 sources (coverage.py, pytest-cov). Worker 3 searches for "CI/CD testing pipelines Python" and generates 4 sources (GitHub Actions, Jenkins, tox). Worker 4 searches for "Python testing anti-patterns" and generates 2 sources (common mistakes blog, testing guidelines).

These 11 searches execute in parallel, each taking 2-5 seconds, completing in under 6 seconds total rather than 22 seconds sequentially. The aggregator then routes the 11 sources to a synthesizer LLM, which reads, deduplicates (removing 1 overlapping source), and produces a ranked report of best practices with citations. Without parallelization, the workflow would chain 4 searches sequentially, taking 22 seconds; parallelization halves latency while maintaining full coverage.

One Level Deeper

Workflow orchestration is a directed acyclic graph (DAG) where nodes are computation units (LLM call, tool call, verifier, router, aggregator) and edges are data dependencies. For the research workflow, the DAG has: (1) 4 parallel search nodes, each with input query and output source list, (2) 1 aggregation node with input = union of 4 source lists, (3) 1 synthesizer node with input = aggregated sources. A router is a conditional node that branches based on input: if query complexity > threshold, route to the "expert search + deep filter" subgraph; otherwise route to the "quick search + simple filter" subgraph.

Each node has a retry policy (if a search times out, retry up to 2 times) and a verification rule (validate that all sources have URL and timestamp). The execution engine schedules nodes: all 4 searches start immediately when the workflow begins; the aggregator does not start until all 4 searches complete. A verifier node may follow the synthesizer to check that the output cites all 10 sources and gives each at least one mention.

Failure Boundary

Workflow orchestration fails when the DAG is incomplete or when the dependencies are incorrect. If the aggregator node does not wait for all 4 searches to complete (due to a missing dependency edge), it may start with only 1 source and produce a narrow report. If a router condition is ambiguous (e.g., "if the task seems complex"), the workflow may route the same query two different ways on successive runs, producing inconsistent branching. Another failure mode occurs when a node's output schema does not match the next node's expected input: if Worker 1 outputs sources as a list of URLs but the aggregator expects a list of source objects with title, URL, and date fields, the aggregator will fail silently or crash.

Long workflows also fail under cascading error conditions: if Worker 2 times out, should Worker 3 and 4 continue or halt? Without an explicit error policy, the workflow behavior becomes undefined. A third failure boundary is resource contention: if all 4 workers try to query the same external API simultaneously with no rate limiting, the API may throttle or reject requests, causing all 4 searches to fail together rather than being retried independently.

From Scaling To Reasoning

The course begins with the old recipe for better LLMs: more compute, more data, and more parameters. It then shifts to methods that make models reason, verify, act, and improve.

Ordinary Problem

You want systems that solve harder tasks, but simply making a base model larger is expensive and eventually gives smaller practical gains.

Naive Picture

Keep adding parameters, data, and compute whenever the model needs to solve a harder problem.

Why It Fails

Scaling can improve base capability, but it does not by itself decide which answer is correct, recover from mistakes, call tools, or complete multi-step work.

First-Principles Move

A model has latent capability, but a deployed system also needs procedures for using that capability. Reasoning traces, search, verifiers, feedback, and tools are procedures for turning possible ability into reliable work.

What Breaks Without It

You confuse model size with system reliability and miss the runtime mechanisms that make agents useful.

Course Role

This is the opening frame for the whole playlist.

Worked Example

Suppose you pre-train a model on 1 trillion tokens at 10^20 compute (parameter × data × training steps). In the old recipe, you observe predictable scaling: more data and parameters reduce test loss. But with a fixed model, inference-time methods unlock hidden capability. Consider a GPT-3-scale model answering hard math problems: with one attempt it solves 15% of problems. By adding reasoning-based procedures (chain-of-thought prompts, search, verification), the same model with 100 samples and a verifier now solves 70% of problems. No retraining. This is not a larger model becoming more capable—it's a system (model + procedures) succeeding where the raw model alone would fail.

The distinction: scaling laws improved the *base model*, but did not guarantee it would answer correctly under pressure, recover from errors, or follow a multi-step plan. A reasoning model (o1-style) combines both: pre-training-scale capability AND trained procedures (chain-of-thought, self-correction, search).

One Level Deeper

The course frames two complementary scaling regimes:

1. **Pre-training scaling law**: Loss ∝ N^(-α) where N is compute, α ≈ 0.07. This means doubling compute reduces loss by ~5%. The model gains broad knowledge but no decision procedure.

2. **Inference-time procedures** (reasoning traces, verification, search): Given a model's latent distribution P(answer | question), procedures extract high-probability correct answers. If a single attempt has pass@1 accuracy p, then with repeated sampling and a perfect verifier, pass@k = 1 - (1-p)^k. For reasoning traces, the model generates intermediate steps s_1, s_2, ..., s_n that act as constraint satisfaction: each step conditions the next, and a verifier can score the chain (process reward) or only the final answer (outcome reward). The course shows that reasoning models trained with RL on verified trajectories learn to reliably generate good chains, combining both regimes.

The key insight: *procedure* (what to output and how to verify it) is orthogonal to *capability* (whether the model can do it). Bigger models have more latent capability; procedures unlock it.

Failure Boundary

The method reaches its limit when the model's distribution does not contain correct answers. If the base model has zero knowledge of a domain (pass@1 = 0), then no amount of sampling or verification will help—pass@k will remain 0. This appears in reasoning models for out-of-distribution questions (e.g., specialized domains the training data did not cover).

Another failure mode: when scaling hits reasoning that is inherently stochastic or requires domain knowledge the model lacks. A smaller model cannot reason about a physics problem it has never seen, no matter how many reasoning traces it generates. For very hard problems, the transcript shows frontier models still outperform smaller models even with large test-time compute budgets. The transition point is problem-dependent and not fully predictable without empirical testing.

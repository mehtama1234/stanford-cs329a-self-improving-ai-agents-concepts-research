Mixture Of Experts

A Mixture of Experts (MoE) model has many small neural networks inside it — think of them as different specialist programs. Each specialist is trained to get good at one kind of task. When the model sees a new piece of text (a 'token'), it doesn't run all the specialists. Instead, a router — a separate program that learned which specialist to pick — sends the token to just a few relevant specialists. Those specialists process it together and send their answer back.

First Principles

A normal model dials all its parameter dials (thousands of millions of them) for every single token. A Mixture of Experts model splits those dials into groups — one group per specialist. For each token, it only adjusts the dials in the few specialists the router picks. This means: the model can have way more total dials than a normal model of the same size, but it only 'turns on' some of them at a time. Fewer dials turning on means less compute needed per token — the model can stay fast even with all those extra specialists packed inside.

Concrete Example

Imagine a model with 100 specialists inside. One specialist learned by reading lots of code. Another learned from poetry. A third from math. When the model sees the token 'function', the router says 'send it to the code specialist and the math specialist' — they process it and vote on the answer. When it sees 'rhyme', the router sends it to poetry and language specialists instead. The model does not use all 100 specialists for every token; it picks the right ones based on what the text is about.

Why It Matters

A normal model with billions of dials is very slow to run — every dial touches every token. A Mixture of Experts model with the same number of total dials can run much faster because only a few specialists activate for each token. This lets builders make larger, smarter models that do not cost as much compute to run. But MoE also has new problems: the router sometimes sends too many tokens to popular specialists and forgets to use others; experts can drift and specialize in useless ways; and if the router makes bad picks, the model gets confused.

Common Misunderstanding

A model with 600 billion total dials does not use all 600 billion dials to process each token. If the router picks 4 specialists out of 200, the model uses only the dials in those 4 specialists — maybe 12 billion. The 600 billion number is the storage size, not the compute cost per token. This is why MoE can scale to huge models without needing huge compute at run time — you pay for specialists you actually use, not for all of them.

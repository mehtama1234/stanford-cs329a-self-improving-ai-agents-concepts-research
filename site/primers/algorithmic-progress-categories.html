Algorithmic Progress Categories

When an AI model gets better at answering questions or solving problems, we need to ask: why did it improve? There are many reasons mixed together. Maybe the way the model is built improved. Maybe the data it learned from improved. Maybe how it was trained changed. Maybe the hardware it runs on got faster. Maybe the thinking strategy got better. Maybe it learned from rewards (a score for right answers). Calling all of this together 'progress' hides which part actually helped.

First Principles

Start with a simple fact: the model performs better at the same amount of computation work. Now trace backward. The improvement came from somewhere. It could be a new architecture — a smarter pattern for how the neural networks are wired. It could be the optimizer — a better recipe for nudging the billions of dials toward right answers. It could be systems and hardware — code that runs faster on the available chips. It could be data — cleaner, bigger, or more carefully chosen text to learn from. It could be training method — a different reward signal or a new way to guide learning. It could be inference — a smarter strategy at test time for picking the best answer. Each of these is a different lever. When you mix them all together without naming which lever moved, you cannot tell what actually caused progress.

Concrete Example

Imagine Model B beats Model A. A scientist announces: 'Algorithmic progress!' But which lever moved? Dig deeper. Model B used synthetic math problems created by humans — carefully designed arithmetic questions — while Model A only learned from raw text. The transformer block inside both models is essentially the same. The win came from data, not from a smarter algorithm. If you label it all as 'algorithmic progress,' you miss the fact that the next step should probably be better data, not a different architecture.

Why It Matters

This matters for forecasting — predicting where AI will go next — and for engineering decisions. If you know data improvements are driving the gains right now, you invest in data pipelines. If hardware speed is the bottleneck, you push for faster chips. If the training method is stuck, you invent new reward signals. The next big jump depends on which lever is closest to its limit. Mislabeling progress hides what is actually stuck and what could move next.

Common Misunderstanding

The trap is using the word 'algorithmic' to mean 'any improvement.' That hides real differences. A newer model beat an older model, so it is progress — but what kind? If you call it all 'algorithmic progress,' you double-count the same gain (maybe data helped and systems helped, but both are called one thing). You also miss when non-algorithmic work — like data collection or hardware engineering — is what actually won. The result: wrong forecasts and misdirected effort.

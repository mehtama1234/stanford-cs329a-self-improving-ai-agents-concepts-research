Reasoning Boundary

A reasoning boundary is the outer edge of what a model is actually able to do. Imagine a model as a student with specific skills from studying: some problems it can solve, some it cannot. The reasoning boundary is the widest circle of problems it could solve if given many, many attempts and different ways of working through them. Not the problems it solves right away, but the ones it gets right at least once if you let it try fifty times.

First Principles

Every model learns patterns from text and ends up with a set of possible answers it can pull from — like a student who studied certain topics. A model's real ability has two layers: (1) which solutions are actually buried in what the model learned, and (2) how easily the model pulls those solutions out. When we use tricks to make a model think step-by-step or guide it with rewards, we're often just making it pull out solutions it already has, not inventing brand new ones. The boundary shows what's possible inside the model; the tricks just make those possibilities happen more often.

Concrete Example

A math model might solve a tricky algebra problem correctly 1 time out of 500 attempts, but fail the other 499 times. That problem sits right at the edge of the model's boundary—it can solve it, but unreliably. A different problem it never solves, even in 500 tries, sits outside the boundary. If you give the model step-by-step hints and make it think longer, you might push that 1-in-500 success up to 10-in-500, but you probably haven't crossed the boundary into brand new problems.

Why It Matters

This idea separates two different things that get confused: does a model actually understand something new, or is it just getting better at finding answers it already had? When a research paper says 'reinforcement learning helped the model solve harder problems,' we need to ask: did RL expand the boundary (teach it truly new reasoning), or just coax out answers that were already hiding in there? The boundary helps us read those papers correctly and understand what the model really learned versus what it simply got better at showing us.

Common Misunderstanding

The reasoning boundary is NOT the same as benchmark accuracy—the score you see on a test. A benchmark usually runs the model once per question, under one setup. The boundary is much wider than that because it asks: if we tried everything the model could possibly do, what would we find? Two models can have the same benchmark score but very different boundaries—one might solve hard problems rarely but correctly, the other might handle only easy questions reliably. The boundary is the true measure of ability; the benchmark is just a narrow peek at it.
